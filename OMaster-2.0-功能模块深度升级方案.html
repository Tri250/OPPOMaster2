一、升级总纲

本方案是「2.0 完整升级规划与功能架构」的模块级深化：为模块清单中的每一组、每个模块给出 2.0 目标态、具体动作、验收标准与依赖关系。既有编号体系（FD/ED/G/M/Q/RISK/R）全部沿用，模块级动作以 MU-xx 编号，与 FD/ED 双向追踪。

2.0 模块升级三原则

  • 生态优先——资源向导入体系、订阅中心、悬浮窗三大「预设生态」模块倾斜（约占动作量 60%），首页/发现等成熟闭环只做治理不做大改。
  • 架构先行——所有新增能力汇入统一数据流（导入 → 校验管道 → 预设库 → 三大消费端），禁止绕过管道直写存储。
  • 每动必测——纯逻辑提取进测试基线；UI 变更必须列入真机回归清单；每个 MU 动作有 DoD。

二、目标功能架构 2.1

五层架构的 2.0 终态。与现状的差异标 新增 / 重构：

L1 入口层：MainActivity（导航宿主）· WelcomeDialog（合规同意）· PillNavBar（底部导航，edge-to-edge ✓）
↓
L2 业务层：HomeScreen · 创建与导入群（万能创建 + 三条导入路径 + 统一校验管道）· DetailScreen · PhotoFrameScreen · SubscriptionScreen（目录预览 ✓ 单源更新 ✓）· ColorWalkScreen · SettingsScreen
↓
L3 核心层：PresetRepository（聚合视图）· PresetParamMapper（悬浮窗纯逻辑 ✓）· FrameRenderer / ColorExtractor · PresetExportService（2.0 新增：预设导出） · CatalogIndexBuilder（2.0 新增：目录索引）
↓
L4 数据层：ConfigCenter（配置中枢）· CustomPresetManager（kotlinx ✓）· 各域 Manager · SubscriptionCatalogReader · PresetRemoteManager + SubscriptionUpdatePolicy（回退保护 ✓）· 迁移：三 Manager Gson 收尾
↓
L5 平台适配层：FloatingWindowService（三形态窗口）· UpdateChecker（应用内更新）· PresetI18n / IconFont · ColorOS17Adapter（2.0 新增：平台差异集中点）

依赖方向规则（红线之一）

  • 只能上层依赖下层；L4 数据层禁止 import 任何 ui/ 包（现状违规 0 处，CI lint 保持）。
  • 三大消费端（悬浮窗 / 相框 / 详情页）对预设库只读展示，写操作只发生在创建与导入群。
  • 平台差异（品牌特判、系统版本分支）必须收敛到 L5 的 ColorOS17Adapter，业务层不得出现 Build.MANUFACTURER 判断（现有 Realme 特判迁移目标）。
